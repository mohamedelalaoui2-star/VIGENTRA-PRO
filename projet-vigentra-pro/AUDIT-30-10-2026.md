## Incompatibilité constatée dans l'ancienne application
L'index.html de la racine utilisait les tables agents et sites avec colonnes full_name, user_id et name, et le README citait le projet Supabase vdoolfdxtqgjqzltxloo. Le projet actif Planning-vigentra possède au contraire agents.nom, agents.Prenom et la table Site avec Nom, Adresse, etc. L'application racine n'est donc pas compatible avec le schéma de Planning-vigentra sans adaptation. Le projet VIGENTRA PRO (vdoolfdxtqgjqzltxloo) est actuellement INACTIVE ; ne pas le réactiver ou y envoyer des données sans décision explicite.

## Observations des conseillers Supabase
### Sécurité
- 1 table RLS activée sans politique détectée : vigentra_company_members. Cela peut être intentionnel si les accès sont exclusivement gérés par une fonction interne privilégiée ; confirmer le modèle avant toute modification.
- 1 fonction SECURITY DEFINER accessible aux utilisateurs authentifiés : vigentra_workspace_owner_id(). Elle est appelée par des politiques de partage et peut activer une invitation en attente. Ne pas révoquer ou modifier sans examiner toutes les dépendances.
- Protection contre les mots de passe compromis désactivée dans les paramètres Auth selon le conseiller. Vérifier l'option et l'impact avant activation.
### Performance
- Plusieurs politiques RLS permissives en doublon (52 constats agrégés par le conseiller).
- 18 clés étrangères sans index de couverture signalées.
- 29 constats de réévaluation inutile de fonctions Auth dans les politiques.
- 5 index signalés comme inutilisés.
Ces constats sont des pistes à examiner, pas des instructions pour supprimer ou modifier automatiquement des politiques ou index.
